CostLens

Manufacturing Cost Investigation Copilot. A public-safe product prototype exploring how an AI agent can help a manufacturing or cost analyst move from “something changed” to “here is the evidence, likely driver and next check.”

01 · THE PROBLEM

Cost investigation looks like data navigation. It is actually reasoning.

When a work order, item cost or accounting result looks wrong, an analyst may need to connect transaction history, cost components, manufacturing context and reference documentation before they can even form a hypothesis.

Primary userCost / manufacturing analyst

Investigates exceptions and explains cost movement.

TriggerUnexpected variance

Actual vs expected, failed processing or work-order question.

SuccessEvidence → action

Understand likely driver and decide what to check next.

02 · PRODUCT THESIS

Ground first. Reason second.

The product should not ask an LLM to “figure it out” from a blank prompt. It should retrieve the relevant structured facts and reference material first, then use the model to synthesize an explanation.

01

Retrieve evidence. Pull cost components, transactions and contextual documentation relevant to the question.

02

Trace drivers. Compare actual vs expected values and identify the largest evidence-backed contributors.

03

Explain uncertainty. Separate known facts from hypotheses rather than presenting every inference as a fact.

04

Recommend checks. Give the analyst a next action that can validate or narrow the hypothesis.

03 · SYSTEM DESIGN

A small architecture, deliberately.

The prototype is designed around a clear separation between factual retrieval and generative reasoning. The data is synthetic so the product can be shared publicly without exposing customer or employer information.

01User question

Natural-language investigation request.

02Router + retrieval

Classify intent; fetch structured facts and relevant docs.

03Reasoning layer

Compare values, trace drivers and assemble evidence.

04Grounded answer

Explain likely cause, evidence and next checks.

Public implementation direction: lightweight web UI + synthetic structured dataset + small knowledge base + LLM/agent layer. Model/provider can be swapped without changing the product contract.

04 · EVALUATION PLAN

AI quality is a product requirement.

For the next build, I will evaluate the system on a synthetic test set covering retrieval, grounding, completeness and failure behavior. The goal is not a benchmark score; it is to make the model’s failure modes visible.

Retrieval hit rate

Did the system retrieve the evidence needed for the answer?

Groundedness

Are material claims supported by retrieved evidence?

Completeness

Did the response address the user’s actual investigation question?

Safe failure

Does the agent abstain or qualify an answer when evidence is insufficient?
